Immutable by design

A read-only core. A deliberate way to change it.

Lanrith treats the OS and its configuration as one versioned system. You choose what runs. Signed images, filesystem verification and a controlled update path help keep it that way.

Read-only at the root.

System files live in a read-only image. dm-verity checks the filesystem as it is read, helping detect tampering. Persistent service data has its own separate storage.

READ-ONLY ROOT / INTEGRITY CHECKS

Your config. Your keys.

Keep network intent in your own Git repository. Review the changes, build the image and sign it with keys you control. The running configuration belongs to that release.

CONFIGURATION IN GIT / OWNER-SIGNED

A new image. A way back.

Updates go to an inactive system slot. A new boot must pass health checks before it becomes the default. The accepted release stays available for fallback.

For your homelab

Keep your weekends for the homelab.

There’s a new service to try, and a houseful of devices that still need to work. We’re building the everyday networking around both.

  1. The everyday networking, joined up.

    Routing, firewall rules, DNS, DHCP and IPv6 are designed as one setup. The integration work belongs in the project, so each homelab doesn’t have to repeat it.

  2. Separate networks. Shared services.

    Keep home, guest and IoT networks separate. Share discovery and service access across the boundaries you choose, with mDNS/DNS-SD considered alongside firewall policy.

  3. IPv4 and IPv6, connected.

    We’re bringing NAT64/NAT46 translation and discovery together for mixed IPv4/IPv6 setups. Supported service paths and device compatibility will be documented as they’re qualified.

A console for answers.
Git for changes.

The local console is being built to explain devices, connections and policy decisions. It observes the router; changes to network intent start with your configuration.
